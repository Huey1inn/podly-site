简体中文

1. 我们读取哪些数据

  • 「健康」中的耳机音量暴露记录(headphoneAudioExposure),只读;
  • 如你主动开启「合并环境噪声」,读取环境噪声暴露记录(environmentalAudioExposure);
  • 应用内的偏好设置,例如语言、排序、通知开关。

podly 不会写入、修改或删除你的健康数据。

2. 数据如何处理

所有统计都在你的设备上完成。podly 不收集、不上传、不分享任何个人数据,不包含分析、广告或第三方 SDK,也没有服务器。

3. 本机存储

  • 设置保存在系统的应用偏好中;
  • 为加快启动,听音记录会缓存到应用的本地容器;
  • 为驱动小组件与手表,会生成一份不含原始健康记录的聚合快照,保存在 App Group 容器中;
  • 只有当你主动导出时,数据才会写到由你选择的文件。

4. 通知与相册

通知全部由本机生成,不使用推送服务器。保存海报时,应用仅请求「添加到相册」权限,不会读取你的相册内容。

5. 儿童

podly 不收集任何用户数据。「儿童/敏感听音模式」只是把安全剂量参考从 80 dB(A) 调整为 75 dB(A)。

6. 数据删除

删除应用会移除本地缓存与设置。健康数据本身由你通过「健康」App 管理。

7. 联系我们

对本政策有疑问,请在 GitHub Issues 留言。

English

1. What we access

  • Headphone audio exposure records from Health (headphoneAudioExposure), read-only;
  • Environmental audio exposure records (environmentalAudioExposure) only if you turn on “Include environmental noise”;
  • App preferences such as language, sorting and notification toggles.

podly never writes, modifies or deletes your health data.

2. How data is processed

All summaries are computed on your device. podly collects nothing, uploads nothing, shares nothing, and contains no analytics, advertising or third-party SDKs. There is no server.

3. On-device storage

  • Settings are stored in the system preferences for the app;
  • Listening records are cached in the app's local container to speed up launch;
  • An aggregate snapshot without raw health records is stored in the App Group container for widgets and the watch app;
  • Data is only written to a file you choose when you export it yourself.

4. Notifications and Photos

Notifications are generated locally; no push server is used. Saving a poster requests add-only access to Photos and never reads your library.

5. Children

podly collects no user data. The child/sensitive mode only changes the dose reference from 80 dB(A) to 75 dB(A).

6. Deleting data

Deleting the app removes its local cache and settings. Health data itself is managed by you in the Health app.

7. Contact

Questions about this policy? Please use GitHub Issues.
